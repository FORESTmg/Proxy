# FOREST's Proxy Auto-updater

Автоматический подбор и переключение прокси-серверов в Windows. Программа
скачивает публичные списки серверов, проверяет их, отбирает рабочие и
поддерживает связь, переключаясь между ними — чтобы падение одного сервера не
обрывало интернет.

**По умолчанию — standalone.** Программа НЕ требует v2rayN: сама хранит список
серверов, сама пишет конфиг ядра Xray, сама запускает/останавливает `xray.exe`
и сама ставит/снимает системный прокси Windows. Есть и опциональный режим
работы через v2rayN — для тех, у кого он уже установлен.

- Лицензия: **GPL-3.0-only** (см. [`LICENSE`](LICENSE))
- Языки: Русский + English (см. [`README.md`](README.md))
- Без сторонних зависимостей Python — только стандартная библиотека
- Один процесс-супервизор вместо трёх отдельных задач Планировщика

> **Перед запуском прочитайте раздел
> [«Безопасность и ограничения»](#безопасность-и-ограничения).** Программа
> меняет системный прокси Windows и управляет процессом прокси-ядра. Так она
> устроена, и об этом сказано прямо.

---

## Для кого это

- Для тех, кто хочет **работающий прокси в Windows без постоянного присмотра**
  — запустил один раз, и программа сама перебирает серверы, когда бесплатные
  умирают.
- Для тех, у кого уже есть ссылки-подписки или настроенный v2rayN и кто хочет,
  чтобы список серверов сам обновлялся, а активный сервер сам переключался.
- Для тех, кто хочет **видеть, что именно делает программа** — она запускает
  обычное ядро Xray и направляет системный прокси Windows на локальный порт;
  никакой скрытой магии и никаких сторонних Python-пакетов.

Она **не подойдёт** тем, кому нужен гарантированно стабильный и быстрый
сервис. Публичные бесплатные серверы нестабильны по своей природе — см. раздел
ограничений.

## Чем отличается от v2rayN

v2rayN — это полноценный GUI-клиент: вы импортируете серверы, выбираете один и
подключаетесь. FOREST's Proxy Auto-updater — инструмент другого рода: это
**фоновый работник** без GUI для управления серверами. Он:

- **сам находит и проверяет серверы**, а не ждёт, пока вы выберете один;
- **держит пул серверов внутри одного работающего ядра** и позволяет Xray
  переключаться между ними, а не перезапускается при каждом изменении;
- **постоянно следит за связью** и перебирает серверы, когда они умирают;
- **управляет системным прокси Windows**, чтобы трафик всей системы шёл через
  рабочее ядро.

Иначе говоря, v2rayN — это клиент, который вы настраиваете; эта программа —
то, что поддерживает список серверов клиента живым. Они не конкуренты, и
программа умеет работать *и поверх установленного v2rayN*, если вам так удобнее
(см. два режима ниже).

## Два режима

Режим выбирается в `config.json` (поле `client.mode`). Без правки кода.

| `client.mode` | Что делает |
|---|---|
| `standalone` (по умолчанию) | Своё ядро Xray, свой стор серверов, своё управление системным прокси. v2rayN не нужен. |
| `v2rayn` | Работа через установленный v2rayN: его база (`guiNDB.db`), его конфиг (`guiNConfig.json`) и его ядро. Перед записью база резервируется. |

В режиме standalone ядро ищется в таком порядке:

1. явный путь из конфига (`client.core`);
2. `bin\xray\xray.exe` рядом с программой;
3. `xray.exe` в `PATH`.

Если ядро не найдено, программа сообщает об этом и указывает страницу
официальных релизов Xray-core. **Программа НЕ скачивает ядро за вас** — вы
кладёте `xray.exe` сами.

## Быстрый старт

Готовый дистрибутив — один `.exe`. Обычный порядок такой:

1. **Скачайте** `.exe` со страницы GitHub Releases проекта.
   2. **Скачивать ничего не нужно — ядро уже внутри.** В `.exe` вшиты Xray v26.3.27
      и обе гео-базы (`geoip.dat`, `geosite.dat`), поэтому standalone-режим работает
      на чистой машине без каких-либо дополнительных файлов. Свою папку `bin\xray\`
      рядом с `.exe` создавайте только если хотите заменить или обновить ядро — эта
      копия имеет приоритет над встроенной.
      Режиму v2rayN файлы не нужны вовсе: ядро даёт сам v2rayN.
3. **Запустите `.exe`.** Windows предупредит о неподписанной программе
   (SmartScreen) — см. раздел безопасности. При первом запуске программа
   создаёт рабочий конфиг из `config.example.json`, **копирует свой `.exe` в
   `%LOCALAPPDATA%\ForestProxyUpdater`** (установка не зависит от папки, куда
   вы распаковали архив), добавляет ярлык в меню «Пуск» и запись в автозапуск
   вида `"%LOCALAPPDATA%\ForestProxyUpdater\ForestProxyUpdater.exe" --run`,
   а затем выполняет первый цикл подбора.
4. После первого цикла **системный прокси Windows направляется на локальный
   порт** `127.0.0.1:10808`, и трафик идёт через отобранные серверы.

Состояние, логи и рабочий конфиг лежат в `%LOCALAPPDATA%\ForestProxyUpdater`.
Папка, в которую вы распаковали программу, остаётся чистой.

Во время работы программа пользуется средствами самой Windows — `curl.exe`
(есть в Windows 10 1803+), а также `PowerShell`/`tasklist`/`taskkill`/`netstat`
для проверки процессов и портов. Прав администратора не требуется.

### Как удалить

Запустите `.exe` с параметром `--uninstall` (или через «удалить», если так
предусмотрено сборкой). Программа остановит ядро, **вернёт системный прокси в
состояние, которое было до первого запуска**, удалит запись из автозапуска,
ярлык, установленный `ForestProxyUpdater.exe` и каталог
`%LOCALAPPDATA%\ForestProxyUpdater`. Если `--uninstall` запущен из самого
установленного `.exe`, файл удалится сразу после выхода программы.

## Как это работает

Один процесс запускает несколько рабочих потоков (это и есть «супервизор»):

- **Менеджер источников** — скачивает файлы подписок по постоянным URL из
  конфига и периодически ищет на GitHub свежие публичные репозитории со
  списками серверов. Источник убирается, если не менялся `sources.stale_days`
  дней.
- **Конвейер проверок** — кандидаты дедуплицируются, при желании отсеиваются по
  TCP-доступности, затем каждый кандидат поднимается как **одноразовый экземпляр
  Xray** на временном порту для замера RTT, лучшие проверяются на скорость, а
  топ — на повторный RTT и доступность YouTube. Чтобы сервер остался, он должен
  пройти пороги по скорости и «дрожанию» (джиттеру).
- **Балансировщик** — прошедшие серверы пишутся в **один** конфиг Xray как пул
  outbound-ов вместе с родным `observatory` (проверкой живости) и балансировщиком
  `leastPing`. Дальше Xray сам направляет новые соединения на живой и быстрый
  узел **без перезапуска**, поэтому связь не рвётся при падении одного узла.
- **Сторож («watch»)** — каждые несколько секунд проверяет локальный порт через
  ядро. Если порт мёртв или процесс ядра исчез, он пересобирает пул за 1–2
  секунды; если проверки продолжают падать — запускает полный цикл подбора. Он
  же следит за скоростью и использует YouTube как «канарейку».
- **Гвард** — более лёгкая периодическая самопроверка, поднимающая связь из
  сохранённых серверов (а в крайнем случае — полный цикл).
- **Поток обновления** — выполняет полный цикл подбора по расписанию
  (`cycle.full_refresh_hours`).

Если балансировщик поднять не удалось, программа откатывается на один сервер, а
затем на **аварийный состав «последний рабочий»**, сохранённый ранее.

### Бесшовность: когда ядро НЕ перезапускается

Перезапуск ядра — это короткий разрыв связи, поэтому он делается только тогда,
когда действительно нужен:

- **Новый конфиг проверяется ядром ДО остановки работающего** —
  `xray run -test -config <файл>`. Мёртвый конфиг не применяется: живое ядро и
  связь остаются нетронутыми (если сборка ядра не понимает `-test`, программа
  автоматически откатывается на проверку запуском на свободных портах).
- **Состав пула не изменился — перезапуска нет вообще.** Программа помнит
  «отпечаток» работающего конфига (`balancer_cfg_sha`) и состав пула
  (`balancer_sig`); если собранный конфиг совпадает с тем, с которым уже
  работает ядро, оно даже не трогается.
- **Заморозка состава пула** (`watch.pool_freeze_s`, по умолчанию 3 ч): пока
  ядро живо и связь есть, пересчёт десятки лучших серверов не приводит к
  перетасовке конфига.
- **Перезапуск только по делу**: активный узел мёртв/ядро не отвечает, состав
  пула изменился и заморозка истекла, либо пользователь сам нажал «Пересобрать»
  в трее.
- **Разрыв измеряется и пишется в лог** в миллисекундах: от снятия старого ядра
  до момента, когда новое ядро приняло клиентский порт, плюс время до
  подтверждённой передачи данных. Фиксированная пауза 300 мс убрана — новый
  процесс стартует сразу, ожидание идёт по факту освобождения порта.

Пример строки в логе: `перезапуск ядра: РАЗРЫВ связи <мс> мс (порт принял
соединения), подтверждение данных <мс> мс, rtt=<мс> мс`.

Исходные настройки системного прокси программа сохраняет при первом
вмешательстве и умеет вернуть их точно.

## Командный интерфейс

Запускайте программу (`.exe` или `python src/v2ray_updater.py` из исходников) с
одним из параметров:

```
--install     разложить в %LOCALAPPDATA%\ForestProxyUpdater (копируется сам .exe),
              создать ярлык и запись автозапуска "<exe> --run", выполнить первый цикл
--uninstall   остановить ядро, вернуть системный прокси, убрать автозапуск,
              ярлык, установленный .exe и каталог программы
--run         обычный запуск: супервизор с рабочими потоками (до остановки)
--once        один полный цикл подбора серверов          (синоним: --auto)
--guard       одна быстрая самопроверка/восстановление
--status      показать текущее состояние
--selftest    прогнать встроенные автотесты
--watch       только сторож (один процесс)
--dry-run     цикл без записи и запуска ядра
--config PATH использовать конкретный config.json
--help        встроенная справка
```

Фоновые процессы запускаются без окон консоли (`CREATE_NO_WINDOW` / семантика
`pythonw`).

## Безопасность и ограничения

Прочитайте это перед запуском. Здесь нет ошибок — так программа устроена, и об
этом стоит знать.

**Программа меняет системный прокси Windows.** Она пишет значения
`ProxyEnable`/`ProxyServer` в ветке реестра
`HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Internet Settings`
и направляет их на свой локальный порт (`127.0.0.1:10808` по умолчанию), чтобы
трафик всей системы шёл через выбранный сервер. Это пользовательская настройка
(прав администратора не требуется), и она влияет на все приложения, которые
следуют системному прокси. Исходное значение сохраняется при первом изменении и
возвращается при `--uninstall`.

**Программа управляет процессом.** В режиме standalone она запускает и
останавливает `xray.exe`. Она снимает только *своё* ядро (по имени своего
конфига) и не трогает другие процессы `xray.exe`.

**`.exe` не подписан цифровой подписью.** Windows SmartScreen и часть
антивирусов будут предупреждать о неподписанной программе, которая меняет
прокси и запускает другой исполняемый файл — для программ такого рода это
ожидаемо. Если вы не доверяете сборке — не запускайте её: соберите сами из
исходников (см. [`docs/BUILDING.ru.md`](docs/BUILDING.ru.md)) и сначала прочитайте код.
Исходники под GPL-3.0 и без сторонних зависимостей.

**Вы направляете свой трафик через чужие серверы, которые не выбирали.** Списки
серверов программа тянет из внешних источников в интернете. Она проверяет
серверы, но **не может проверить, кто именно владеет сервером**. Тот, кто
держит прокси-узел, может видеть и изменять проходящий через него трафик. Не
отправляйте конфиденциальный трафик через серверы, которым не доверяете. Сама
программа ничего не шифрует — она полагается на защиту транспорта (TLS/REALITY),
заданную тем, кто публиковал сервер.

**Бесплатные серверы нестабильны.** Публичные бесплатные узлы постоянно падают,
блокируются, режут скорость или исчезают. Будьте готовы, что связь будет
неровной, переключения — частыми, а иногда рабочего сервера не найдётся вовсе.
Это свойство серверов, а не программы. Для стабильного и быстрого соединения
используйте платного провайдера.

**Настройки под конкретного провайдера по умолчанию выключены и включаются под
вашу ответственность.** Есть две опции под особые условия сети, и обе
**выключены в поставляемом конфиге**:

- `test.gate_urls` (по умолчанию пусто) — «шлюз»: домены, до которых сервер
  обязан дотянуться; так отсеиваются серверы, не умеющие открыть конкретный
  сайт.
- `watch.ru_direct` (по умолчанию `false`) — пускать российские домены/IP
  напрямую, минуя прокси; требует наличия гео-баз (`geosite.dat`, `geoip.dat`).

Обе меняют маршрутизацию трафика в *вашей* сети. Включая их, вы делаете это на
свою ответственность и должны понимать правила своего провайдера.

**Назначение.** Программа предназначена для законного использования — например,
чтобы поддерживать рабочее соединение с серверами, которыми вы вправе
пользоваться. Ответственность за то, как вы её используете, и за соблюдение

## FAQ

Короткие ответы; полный список — в [`docs/FAQ.ru.md`](docs/FAQ.ru.md).

- **«Не находит серверы».** Первому запуску нужны несколько минут и рабочий
  интернет; бесплатные списки ненадёжны. Смотрите `logs/main.log`. См.
  [`docs/FAQ.ru.md`](docs/FAQ.ru.md).
- **«После запуска нет интернета».** Программа направляет системный прокси на
  свой локальный порт; если ни один сервер не поднялся, прокси ведёт в пустоту.
  Выполните `--uninstall`, чтобы вернуть прокси, или см. FAQ.
- **«Антивирус ругается».** Сборка не подписана. См. раздел безопасности и
  [`docs/FAQ.ru.md`](docs/FAQ.ru.md).
- **«Как это удалить?»** Выполните `--uninstall`.
- **«Где логи?»** `%LOCALAPPDATA%\ForestProxyUpdater\logs\main.log`.
