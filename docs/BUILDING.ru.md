# Сборка и выпуск релиза

Этот документ объясняет, как собрать однофайловый `.exe` самостоятельно и как
опубликовать релиз на GitHub. Он написан для сопровождающего, а не для конечного
пользователя.

Сборка даёт **неподписанный** `.exe`. Подпись не входит в задачи проекта, поэтому
Windows SmartScreen и часть антивирусов будут предупреждать о неподписанной
программе — это ожидаемо (см. раздел безопасности в
[`../README.ru.md`](../README.ru.md)).

Всё, что нужно для сборки, лежит в `packaging/`.

## Что нужно

- **Windows x64** (программа только для Windows; в исходниках есть POSIX-порт,
  но здесь он не собирается).
- **64-битный Python 3** (`build.ps1` ищет его в таком порядке: аргумент
  `-Python`, переменная окружения `FOREST_PYTHON`, `py -3.12`, `py -3.13`,
  `py -3.11`, `py -3`, `python`, `python3`). Подойдёт Python 3.10 или новее; в
  эталонной сборке использовался 3.12.
- **Интернет — один раз**, чтобы скачать PyInstaller и официальный релиз
  Xray-core.

PyInstaller вы **не** ставите сами: скрипт сборки поднимает изолированное
окружение и ставит его туда по пину (`requirements-build.txt`, сейчас
`pyinstaller==6.22.3`). У самой программы сторонних Python-зависимостей в
рантайме **нет** (только стандартная библиотека).

## Собрать

Вся сборка — это один скрипт `packaging/build.ps1` с обёрткой `.bat`. Простейший
вариант:

```bat
packaging\build.bat
```

Или напрямую:

```powershell
powershell -ExecutionPolicy Bypass -File packaging\build.ps1
powershell -ExecutionPolicy Bypass -File packaging\build.ps1 -Clean      :: пересобрать с нуля
powershell -ExecutionPolicy Bypass -File packaging\build.ps1 -NoVenv    :: без venv, в системный Python
$env:FOREST_PYTHON='C:\Path\to\python.exe'; powershell -File packaging\build.ps1
```

Скрипт **идемпотентен** — повторный запуск ничего не ломает и не требует ручных
шагов. По порядку он:

1. находит 64-битный Python 3;
2. создаёт изолированное окружение сборки `packaging\.build-venv` и ставит в
   него PyInstaller (пин из `requirements-build.txt`), если его там ещё нет;
3. если нет ядра — качает официальный релиз XTLS/Xray-core (`fetch_core.py`);
   если нет иконки — рисует `app.ico` (`make_icon.py`);
4. запускает PyInstaller по спеке `ForestProxyUpdater.spec`;
5. кладёт результат в `packaging\dist\` и печатает его размер и SHA-256, дублируя
   их в `dist\build-report.json` и `dist\ForestProxyUpdater.exe.sha256`.

Готовый файл — **`packaging\dist\ForestProxyUpdater.exe`**.

Эталонная сборка в этом репозитории:

| Поле | Значение |
|---|---|
| Размер | 30 709 514 байт (29,29 МиБ) |
| SHA-256 | `06dbfc2a46820b1106177a5f269840d33108a99085aa478f197e3742b21bb27d` |
| Собрано (UTC) | 2026-10-16T18:34:54Z |
| PyInstaller | 6.22.3 |
| Базовый Python | Python 3.12 (64-бит) |
| Xray-core | v26.3.27 |
| Компоновка | onefile, `console=False` |

## Что внутри одного `.exe`

Спека `ForestProxyUpdater.spec` собирает onefile + `console=False` (окна консоли
нет); иконка и ресурс версии Windows приклеены к EXE.

| Внутри | Куда ложится | Кто это находит |
|---|---|---|
| код `src/*.py` | PYZ-архив | «плоские» импорты `import config`, `import clientwrite`, … |
| ядро Xray | `bin\xray\xray.exe` | `config.find_core()` |
| гео-базы | `bin\xray\geoip.dat`, `bin\xray\geosite.dat` | `clientwrite.geo_asset_dir()` (каталог рядом с ядром) |
| лицензия ядра (MPL-2.0) | `bin\xray\LICENSE` | — |
| `config.example.json` | корень пакета | `config.example_config_path()` (первый запуск без конфига) |

Пути подобраны под уже существующий код: при распаковке onefile `__file__` равен
файлу внутри `sys._MEIPASS`, поэтому `config.BASE_DIR` == каталог распаковки, а
`bin\xray\` лежит ровно там, где его ищут.

## Воспроизводимость: `.exe` не побитово идентичен между сборками

PyInstaller вшивает в PE штамп времени, поэтому `build.ps1` фиксирует
`SOURCE_DATE_EPOCH` (значение `1735689600`, т.е. 2025-01-01T00:00:00Z), чтобы
штамп не «плясал» между сборками. **Побитовой идентичности `.exe` это НЕ даёт**:
порядок обхода каталогов при упаковке архива у PyInstaller не детерминирован,
поэтому SHA-256 **может меняться между сборками** (проверено на этом проекте).
Стабильно другое: *процесс* повторяем и не требует ручных шагов, а содержимое
архива — то же.

Итог: идемпотентен **процесс**, а не **байты**. Чтобы убедиться, что вшитые ядро
и гео-базы побайтово совпадают с официальным релизом, запустите `verify_bundle.py`
(см. ниже) — он сверяет их с пином из `core.lock.json`.

## Проверить собранное

```bat
cd packaging\dist
copy ..\..\config.example.json .
ForestProxyUpdater.exe --selftest --config config.example.json
ForestProxyUpdater.exe --status   --config config.example.json
```

Ожидаемо: `--selftest` печатает `ВСЕ ПРОВЕРКИ ПРОЙДЕНЫ` и возвращает код 0 (те
же 90 проверок, что при запуске из исходников), а `--status` показывает режим,
путь к **вшитому** ядру (внутри `%TEMP%\_MEI...\bin\xray\xray.exe`), размер пула
и состояние системного прокси.

Чтобы убедиться, что ядро и гео-базы внутри `.exe` побайтово совпадают с
официальным релизом:

```powershell
packaging\.build-venv\Scripts\python.exe packaging\verify_bundle.py
```

## Обновить ядро Xray-core

```bat
packaging\.build-venv\Scripts\python.exe packaging\fetch_core.py --force
```

Скачивание разрешено **только** с
`github.com/XTLS/Xray-core/releases/download/...` (проверка хоста и пути в
`fetch_core.py`). Архив сверяется по SHA-256 с пином из `core.lock.json`. Чтобы
перейти на новую версию: поправить `core_version.txt`, скачать, затем
`fetch_core.py --print-lock > core.lock.json` и пересобрать.

`vendor\` в git не хранится (там ~63 МиБ бинарников) — он детерминированно
воспроизводится из пина.

## Сборка без PyInstaller (запуск из исходников)

Для разработки собирать ничего не нужно — запускайте модули напрямую:

```
python src\v2ray_updater.py --status
python src\v2ray_updater.py --once --dry-run
python src\v2ray_updater.py --selftest
```

`--install` из дерева исходников копирует `.py`-файлы в
`%LOCALAPPDATA%\ForestProxyUpdater\src`, создаёт ярлык в меню «Пуск» и запись в
автозапуске и выполняет первый цикл.

## Опубликовать релиз на GitHub

1. **Обновить changelog.** Добавьте записи релиза в `CHANGELOG.md` (новая секция
   `## [x.y.z] — YYYY`) и закоммитьте её.
2. **Поднять версию** в changelog и везде, где проект её фиксирует.
3. **Проставить тег** релиза (аннотированный, совпадающий с версией):
   ```
   git tag -a v1.0.0 -m "FOREST's Proxy Auto-updater 1.0.0"
   git push origin v1.0.0
   ```
4. **Создать GitHub Release** для тега:
   ```
   gh release create v1.0.0 "packaging\dist\ForestProxyUpdater.exe" ^
      --title "FOREST's Proxy Auto-updater 1.0.0" ^
      --notes-file RELEASE_NOTES.md
   ```
   (или через веб-интерфейс: *Releases → Draft a new release*, выбрать тег,
   прикрепить собранный `.exe` как бинарный ассет).
5. **Прикрепить `.exe` как ассет релиза** — не просто ссылайтесь на артефакт
   сборки, который истекает. Ядро уже внутри одного `.exe`, поэтому отдельно
   ничего возить не нужно; если публикуете ещё и контрольную сумму, приложите
   `dist\ForestProxyUpdater.exe.sha256`.

### Что писать в описании релиза

Держитесь фактов и краткости. Хорошая заметка о релизе покрывает:

- **Что это**, в одном-двух предложениях (автоматический подбор прокси для
  Windows; по умолчанию standalone).
- **Требования**: Windows 10/11. Ядро Xray уже вшито в один `.exe` — вручную
  ничего добавлять не нужно.
- **Установку**: скачать, запустить, и что Windows покажет предупреждение о
  неподписанной программе.
- **Удаление**: запустить с `--uninstall`; он возвращает системный прокси.
- **Прямое предупреждение**: программа намеренно меняет системный прокси Windows
  и запускает процесс `xray.exe`; бесплатные серверы нестабильны; используйте по
  закону.
- **Изменения в этом релизе**: соответствующие пункты из `CHANGELOG.md`
  (возможности, исправления, известные ограничения).
- **Проверку**, если публикуете контрольные суммы: короткий список SHA-256 для
  приложенных файлов.

Не обещайте надёжность, скорость или анонимность, которых программа дать не
может — честная подача в [`../README.ru.md`](../README.ru.md) и есть эталон.

## Замечания и оговорки

- **`build.ps1` сохранён в UTF-8 с BOM.** Иначе Windows PowerShell 5.1 читает
  кириллицу как ANSI, принимает её байты за «умные кавычки» и ломает разбор
  строк. При правке файла BOM нужно сохранить.
- Основной путь (`build.ps1`/`build.bat` через `packaging\.build-venv`, включая
  установку PyInstaller с нуля) проверен и отлажен. Флаг `-NoVenv` (PyInstaller в
  системный Python) в этой итерации не прогонялся.
- `--status` при первом запуске создаёт каталог программы
  `%LOCALAPPDATA%\ForestProxyUpdater\{state,logs}` — это её штатное поведение;
  системный прокси команда только читает.
